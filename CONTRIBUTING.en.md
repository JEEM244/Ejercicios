# Maintenance guide

This repository is a study library. Changes should improve accuracy, clarity, or practical usefulness.

## Before adding content

1. Check whether the topic already exists.
2. Identify its primary area and prerequisites.
3. Use the appropriate template.
4. Add links to related topics.
5. Update the English version when applicable.

## Writing

- Explain one idea per section.
- Use plain terms before specialized vocabulary.
- Include small, commented examples.
- Explain why code works, not only what it does.
- Separate general concepts from version- or platform-specific differences.
- Avoid long paragraphs and repetition.

## Code

- Every example needs a clear purpose.
- State how to run it and what it requires.
- Never claim code was tested unless it was executed.
- Avoid unnecessary dependencies.
- Keep naming and formatting consistent.

## Exercises

- Assign a new, unique ID.
- The statement must not reveal the solution.
- Include inputs, outputs, and test cases.
- Store the solution separately.
- Explain common mistakes and relevant decisions.

## Architecture changes

When scope, structure, or an important convention changes, update `SPEC.md`, `SPEC.en.md`, and the change log.

## Safety

Networking and administration examples must use owned or authorized systems.
